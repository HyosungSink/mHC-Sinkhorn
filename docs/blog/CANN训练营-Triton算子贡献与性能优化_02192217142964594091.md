以`_fwd_kernel_stage2`为例，首先以终为始，我们看一下提交贡献的目录结构：

```shell
fwd_kernel_stage2/
├── README.md
├── conftest.py
├── test_common.py
├── utils.py
├── kernel/
│   ├── __init__.py
│   └── _fwd_kernel_stage2.py
├── tests/
│   ├── test__fwd_kernel_stage2.py
│   ├── test_accuracy_fwd_kernel_stage2.py
│   ├── test_benchmark_fwd_kernel_stage2.py
│   └── test_fwd_kernel_stage2_v2.pt
└── docs/ #设计文档                             
```

在根目录下，有README.md，它是算子的对外说明文档，供使用者快速了解算子全貌。另外还有3个代码文件：conftest.py是pytest全局配置文件，当我们使用活动方的输入输出pt文件时，`--ptfile_path`命令行选项需要此文件。`test_common.py`是测试公共工具库，提供Tensor转移到设备，性能采集，精度比较等功能。`utils.py`是性能基准测试框架，定义算子类型分类，性能阈值和对比等功能。

在kernel/目录下面，就是我们的重点：算子实现。本算子在优化前采用活动方提供的pt文件，性能可以达到3us左右，这里面还要包含多核启动的固定开销等，所以个人理解其实优化的空间并不大了。所以本文主要讲贡献基本流程，而下篇主要讲性能优化。略过`kernel/__init__.py`初始化文件，`kernel/_fwd_kernel_stage2.py`是算子的核心实现文件，其中`_fwd_kernel_stages2_1d`是使用`@triton.jit`装饰的Trion kernel，它按照昇腾NPU的模式，采用1D Grid分核，核内通过 `pid // NUM_HEADS` 和 `pid % NUM_HEADS` 反推 batch/head 索引，过程中使用 `tl.range()` 遍历 KV split（支持编译器软件流水线化），实现 Online Softmax 跨 split 归约：逐 split 更新 e_max、e_sum、acc，最终写出 o 和 lse。

最后是tests/目录，里面是测试脚本和数据。`test__fwd_kernel_stage2.py`使用pt文件进行功能/精度测试和性能测试。`test_accuracy_fwd_kernel_stage2.py`自行构造测试用例的输入进行精度测试，精度对比是Triton kernel的执行结果和pytorch的实现进行对比。`test_benchmark_fwd_kernel_stage2.py`使用 `utils.Benchmark` 框架进行性能基准测试，根据性能测试用例串行执行，分别跑torch_op和triton_op，并执行profiler采集性能数据，进行SpeedUp计算和阈值断言。最后`tests/test_fwd_kernel_stage2_v2.pt`是活动方预生成的测试数据文件（PyTorch 序列化格式），包括input_data,grid,gpu_output等。
