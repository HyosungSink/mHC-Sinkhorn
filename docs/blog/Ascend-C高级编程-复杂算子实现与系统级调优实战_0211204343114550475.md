2. 核函数启动配置与负载均衡

核函数的grid和block配置直接影响负载均衡和性能。

cpp

```
// 经验法则：
// 1. block数应 >= AI Core数量，以充分利用所有计算单元
// 2. 每个block处理的数据量应足够大，以摊销核函数启动开销
// 3. 数据应能均匀划分，避免某些block处理过少数据（尾部分布问题）

// 最佳实践：使用动态任务分配
class DynamicSchedulerKernel {
    __aicore__ inline void Process() {
        int32_t coreId = GetBlockIdx();
        int32_t totalCores = GetBlockNum();
        
        // 使用原子操作获取下一个任务块
        __global__ atomic_int task_counter;
        while (true) {
            int32_t task_id = atomic_add(&task_counter, 1);
            if (task_id >= total_tasks) break;
            
            // 处理第task_id个任务块
            process_task(task_id);
        }
    }
};

关键分析点：

- 核函数排队延迟：Host侧任务下发是否及时？
- 数据搬运耗时占比：Copy-in/out是否成为瓶颈？考虑双缓冲。
- 计算单元利用率：Vector或Cube单元是否大部分时间空闲？
- L1/L2缓存命中率：数据局部性是否良好？
- 核间同步等待：是否存在barrier导致的空闲？

Transformer中的Attention计算是典型的复杂算子，涉及矩阵乘、Softmax、缩放等操作。

优化策略：

- 算子融合：将Q*K^T、缩放、Mask、Softmax、与V的相乘融合为一个核函数，避免中间结果写回全局内存。
- 分块计算：对于长序列，将Q、K、V分块处理，利用L2缓存减少内存带宽压力。
- 数值优化：Softmax计算时减去最大值防止溢出，使用高精度中间累加。
- 核函数协作：不同的注意力头可以分配到不同的AI Core上并行计算。
cpp

```
// 简化版的Attention核函数结构
class MultiHeadAttentionKernel {
    __aicore__ inline void Process() {
        // 每个核函数处理一个或多个注意力头
        int head_id = GetBlockIdx();
        
        // 1. 搬入当前头的Q, K, V切片
        load_query_slice(head_id);
        load_key_slice(head_id);
        load_value_slice(head_id);
        
        // 2. 计算Q*K^T (分块GEMM)
        //    使用Cube单元进行高效矩阵乘
        compute_attention_scores();
        
        // 3. 应用缩放、Mask和Softmax
        //    Softmax在向量单元上逐行计算
        apply_softmax();
        
        // 4. 计算注意力输出: Attn * V
        compute_attention_output();
        
        // 5. 将输出写回全局内存（或直接传递给下一个核函数）
        store_output(head_id);
    }
};
