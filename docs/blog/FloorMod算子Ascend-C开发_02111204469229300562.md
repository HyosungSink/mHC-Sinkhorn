# 一 TBE算子分析

## 1. 核心功能与定义
* **算子名称**: `FloorMod`
* **支持数据类型**: 
  * 标准支持: `float16`, `float32`, `int32`, `bfloat16`
  * 条件支持: `int64`
* **广播机制**: 支持自动广播 (`Broadcast`)，能够处理 `x1` 和 `x2` 形状不一致的情况。


## 2. 计算逻辑详解 (`floor_mod_compute`)

### A. 通用浮点与 Int32 路径 (`_mod` 函数)
* **精度提升**: 若输入为 `float16` 且硬件支持，优先将其转为 `float32` 进行中间计算，以减少累积误差。
* **计算流程**:
  1. **除法与取整**: `res_quot = floor(x1 / x2)`
  2. **计算余数**: `res_rem = x1 - (res_quot * x2)`
* **Int32 特殊处理**: 在最后计算余数 (`vsub`) 时，会使用原始的整数输入进行运算，而不是使用浮点中间值，这避免了浮点转换导致的整数精度丢失。

### B. Int64 路径
* 针对 `int64` 类型，直接调用 `tbe.vmod` 接口。

---

## 3. 关键补丁与特殊处理

### A. Ascend 910B/910C 硬件补丁

1. **Inf/NaN 处理**:
   * 若 `x2` 为 Inf，结果直接取 `x1`。
   * 若 `x1` 为 Inf，结果置为 `NaN`。
2. **符号修正**:
   * 核心目标是确保 `sign(res) == sign(x2)`。
   * **逻辑**: 计算 `sign_diff`。如果余数非零且符号与除数不一致，则执行 `res = res + x2`。

### B. Int32 大数精度保护
当 `int32` 数值超过2^{24} (16,777,216) 时，Float32 无法精确表示。
* **策略**: 引入 `FP32_MAX_VALID` 常量。
* **算法**: 采用分步取模策略（先对 2^{24} 取模，再处理剩余部分），通过软件算法规避硬件浮点尾数位限制，从而在不支持高精度模式的情况下也能算对大整数。

# 二 FloorMod算子设计
| 名称 | 类别 | 类型 (dtype) | 格式 (format) | 形状 (shape) |
| :--- | :---: | :--- | :---: | :---: |
| x1 (input) | 输入 | bf16, fp16, fp32, int32 | ND | All |
| x2 (input) | 输入 | bf16, fp16, fp32, int32 | ND | All |
| y (output) | 输出 | bf16, fp16, fp32, int32 | ND | All |

结合Ascend总结为以下场景：

| 场景分类 | 核心逻辑描述 | 所需核心 API |
| :--- | :--- | :--- |
| 通用基础计算 | 执行 floor(x/y) 并求余 | Div, Floor, Mul, Sub |
| 精度提升 (Cast) | 对于低精度类型 (fp16/bf16)，先转为 fp32 计算以减少舍入误差 | Cast (RoundMode: CAST_NONE / CAST_RINT) |
| 高精度 Int32 拆分 | 解决 int32 > 2^24 时转 float 丢失精度的问题，利用 2^24 进行分段取模 | ShiftRight, ShiftLeft, Add, Sub |
| 特殊边界处理 | 处理 x 或 y 为 Inf/NaN 的情况，以及 y=0 的保护 | Abs, Compare, Select |
| 符号修正 (Sign) | 确保结果符号与除数 y 一致 | Mul, Compare, Add, Select |

# 四 FloorMod算子优化

- 尽可能的复用中间Tensor
- Shape较大的时候，开启双缓存，较小的时候关闭，减少串行时间
- 优化内部IF-Else，减少分支判断(Select替代)
- 尽可能让多个MTE同时工作，在Int32高精度模式下，指令较多，需要重排指令，增加并行度
