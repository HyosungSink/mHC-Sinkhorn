# 背景

  2025年CANN训练营第二季社区任务SelectV2（任务编号05）要求，在“Atlas A2训练系列产品/Atlas 800I A2推理产品/A200I A2 Box异构组件”平台上用Ascend C实现，性能要求对标CANN内建TBE算子。

  
# 一、算子分析

  
## 一）、内置TBE算子分析

  通过对SelectV2算子TBE版本的功能分析，数学表达式：out(i)=if(condition(i))? self(i) : other(i)。

  当前支持的能力如下：
        ①condition支持bool格式的输入，self支持bfloat16, float16, float32, int32, uint32, int16, uint16, int8, uint8, bool, int64, uint64 十二个种格式的输入，other支持bfloat16, float16, float32, int32, uint32, int16, uint16, int8, uint8, bool, int64, uint64 十二种格式的输入。 根据任务书，int64, uint64暂不支持。
        ②SelectV2算子涉及到对输入数据进行广播（输入数据的shape调整到相同大小），根据任务书，暂不支持。
        ③根据条件选取self或other中元素并返回（支持广播）。在对输入数据进行广播操作后，调用vsel接口实现相应的表达式。

## 三）、Ascend C实现

  Ascend C算子实现，包括Host侧Tiling实现，和Kernel侧实现两部分。

  
### **1、host侧Tiling方案**

  根据任务书要求，不处理广播的情形，这样算子计算过程不涉及数据的维度信息，故在host侧将数据视为一维向量，仅考虑数据个数，不考虑数据维度信息。

  1）核间切分策略——优先使用满核的原则

  **任务均分：**coreNum 根据输入长度和块大小动态调整，确保每个核心处理的数据块数均匀。
        **批量搬运：**tileBlockNum 和 tileDataNum 计算单次搬运的数据量，通过 finalSmallTileNum 和 finalBigTileNum 确定小核/大核的搬运次数，将多次搬运合并为批量操作，减少冗余开销。尾块的处理逻辑确保不完整块也能被合并到计算流程中，避免数据碎片。

  2）核内切分策略——充分使用UB空间的原则

  需要考虑不同硬件的UB大小不同、是否开启double buffer、kernel侧API实现过程中是否需要临时数据的储存，综合考虑单核内切分的大小。
      **UB内存大小获取：**通过GetCoreMemSize函数获取UB内存的大小，用于后续的数据切分计算。
     **Tile块计算：**根据UB内存大小和预定义的BLOCK_SIZE（最新要求是通过BLOCK_SIZE = Ops：：Base：：GetUbBlockSize(context);获取）及BUFFER_NUM和不同类型下的ubDataNum，计算出每个Tile块的数据数量。
      **数据切分：**将输入数据按照计算出的Tile块大小进行切分，计算出每个core需要处理的数据块数量和最后一个block的剩余数据量。
      **设置切分参数：**将计算出的切分参数（如每个core的数据量、Tile块大小等）设置到SelectV2TilingData对象中。
      这些策略确保了数据在多个核心之间的均匀分布，并且在单个核心内进行了合理的切分，以提高并行处理的效率。

  3）tilingkey规划策略——不进行tilingkey划分，在kernel侧根据输入数据的类型走不同的编译分支。

  
### **2、kernel侧设计方案**

  包括Init和Process两个阶段，其中Process包括数据搬入（CopyIn）、计算（Compute）、搬出（CopyOut）三个阶段。由于对应的Ascend C开发的硬件中AscendC::Select只支持half和float数据的输入。float和float16直接调用AscendC::Select的Api实现，bfloat16、int16和uint16可以使用ReinterpretCast强制类型转换成float16，再调用AscendC::Select的Api实现；int32，uint32可以使用ReinterpretCast强制类型转换，当成float，调用AscendC::Select的Api实现；bool、int8和uint8可以直接调用AscendC::Cast，转换成float16类型，再调用AscendC::Select的Api实现，int64和uint64暂不支持。

# 二、代码实现

  本次最终代码需要提交到gitcode的cann/ops-math仓的\experimental\math，所以需要按代码仓的要求编码，提交交付物，具体要求可参考代码仓的“AI Core算子开发指南”。算子开发流程分为七步。

  
## 一）、工程创建

  首先完成环境部署（本次活动提供了基于华为云的开发镜像），git clone代码仓到本地，然后创建算子目录，方便后续算子的编译和部署。

  在代码仓目录下，执行：bash build.sh --genop=experimental/math/select_v2，执行完成后，会在工程的experimental/math 目录下，生成select_v2的算子工程目录。

## 三）、Tiling实现

  因NPU中AI Core内部存储空间有限，无法一次性将整个张量数据加载到计算单元中处理，因此需要将输入张量切分为多个小块（Tile），逐块进行计算，这一过程称为Tiling。用于指导数据切分的算法称为Tiling策略或Tiling算法，其决定了如何将输入数据切分为多个计算块，并指导Kernel如何分配内存、调度计算任务。Tiling与Kernel之间通过TilingData结构体进行信息传递。

  Tiling一共需要三个交付件：${op_name}_tiling.cpp ${op_name}_tiling_key.h ${op_name}_tiling_data.h。本算子实现如下：

  **交付件1**：select_v2_tiling.cpp——Tiling主要切分逻辑，该文件在op_host目录下。

  **交付件2：**select_v2**_**tiling_key.h

  TilingKey是一个算子内为了区分不同的实现而将kernel代码进行区分的方法，kernel侧可以通过TilingKey来选择不同的算法逻辑，该文件在op_kernel目录下。

## 四）、Kernel实现

  Kernel是算子在NPU执行的核心部分，负责张量数据的加载、计算和存储，是算子功能实现的最终载体。Kernel的实现需要与Tiling策略紧密配合，根据Tiling提供的TilingData、TilingKey信息进行内存分配和计算调度。
