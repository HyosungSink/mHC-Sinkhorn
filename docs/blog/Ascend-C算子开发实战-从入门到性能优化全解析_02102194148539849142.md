# 1 Ascend C概述与核心优势

Ascend C是CANN（Compute Architecture for Neural Networks）针对算子开发场景推出的编程语言，它原生支持C和C++标准规范，通过多层接口抽象、自动并行计算、孪生调试等关键技术，​​极大提高了算子的开发效率​​，帮助AI开发者低成本完成算子开发和模型调优部署。

与CUDA开发的算子运行在GPU上类似，基于Ascend C开发的算子可以通过CANN异构计算架构运行在昇腾AI处理器（NPU）上。Ascend C的主要优势包括：

- ​​C/C++原生支持​​：最大化匹配用户开发习惯，降低学习成本
- ​​硬件差异屏蔽​​：编写一套代码可在不同硬件架构上执行，保障代码延续性
- ​​多层级API设计​​：提供从简单到灵活的多层级API接口，满足不同开发需求
- ​​孪生调试能力​​：CPU侧可模拟NPU行为，减少对NPU资源的依赖

## 2 昇腾AI硬件基础与编程模型

### 2.1 昇腾AI处理器架构

昇腾AI处理器最核心的部件是​​AI Core​​，它是神经网络加速的计算核心。每个AI Core包含三个关键计算单元：

- ​​标量计算单元​​：执行地址计算、循环控制等标量计算工作
- ​​向量计算单元​​：负责执行向量计算
- ​​矩阵计算单元​​：负责执行矩阵运算
AI Core内部还包含​​本地内存(Local Memory)​​和​​数据搬运单元(DMA)​​。Local Memory因为靠近计算单元，带宽非常高，但容量相对较小（通常是几百K到1M）。DMA搬运单元负责在Global Memory和Local Memory之间搬运数据。

### 2.2 并行计算模式

Ascend C支持两种主要的并行计算模式：

- ​​SPMD数据并行​​：将数据分片，每片数据经过完整的数据处理流程。多个AI Core共享相同的指令代码，每个核上的运行实例唯一的区别是block_idx（内置变量）不同。
- ​​流水线并行​​：把算子核内的处理程序分成多个流水任务（Stage），以张量(Tensor)为数据载体，以队列(Queue)进行任务之间的通信与同步，以内存管理模块(Pipe)管理任务间的通信内存。

## 4 第一个Ascend C算子：矢量加法实现

### 4.1 算子分析与设计

我们以实现简单的矢量加法算子为例，介绍Ascend C算子开发全流程。首先进行算子分析：

- ​​数学表达式​​：z = x + y
- ​​输入输出​​：- 输入x: shape(8, 2048), dtype: half, format: ND
- 输入y: shape(8, 2048), dtype: half, format: ND
- 输出z: shape(8, 2048), dtype: half, format: ND

- ​​核函数名称​​：add_custom
- ​​所需接口​​：DataCopy（数据搬移）、Add（矢量加法）、AllocTensor/FreeTensor（内存管理）、EnQue/DeQue（队列管理）

### 4.2 核函数开发

核函数是Ascend C算子设备侧的入口，需要按照特定规则编写：

```
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z)
{
    KernelAdd op;
    op.Init(x, y, z);
    op.Process();
}

```

其中：

- `__global__`函数类型限定符标识这是一个核函数
- `__aicore__`函数类型限定符标识该核函数在设备端AI Core上执行
- `GM_ADDR`是宏定义，表示全局内存地址指针

### 4.3 算子类实现

接下来实现算子类，包含初始化函数和核心处理函数：

```
class KernelAdd {
public:
    __aicore__ inline KernelAdd() {}
    
    // 初始化函数，完成内存初始化相关操作
    __aicore__ inline void Init(GM_ADDR x, GM_ADDR y, GM_ADDR z)
    {
        // 多核并行，设定当前核上Global Memory的起始地址以及长度
        xGm.SetGlobalBuffer((__gm__ half*)x + BLOCK_LENGTH * GetBlockIdx(), BLOCK_LENGTH);
        yGm.SetGlobalBuffer((__gm__ half*)y + BLOCK_LENGTH * GetBlockIdx(), BLOCK_LENGTH);
        zGm.SetGlobalBuffer((__gm__ half*)z + BLOCK_LENGTH * GetBlockIdx(), BLOCK_LENGTH);
        
        // 通过pipe为queue分配内存
        pipe.InitBuffer(inQueueX, BUFFER_NUM, TILE_LENGTH * sizeof(half));
        pipe.InitBuffer(inQueueY, BUFFER_NUM, TILE_LENGTH * sizeof(half));
        pipe.InitBuffer(outQueueZ, BUFFER_NUM, TILE_LENGTH * sizeof(half));
    }
    
    // 核心处理函数，实现算子逻辑
    __aicore__ inline void Process()
    {
        constexpr int32_t loopCount = TILE_NUM * BUFFER_NUM;
        
        // 多个任务实现流水并行
        for (int32_t i = 0; i  xLocal = inQueueX.AllocTensor();
        LocalTensor yLocal = inQueueY.AllocTensor();
        
        DataCopy(xLocal, xGm[progress * TILE_LENGTH], TILE_LENGTH);
        DataCopy(yLocal, yGm[progress * TILE_LENGTH], TILE_LENGTH);
        
        inQueueX.EnQue(xLocal);
        inQueueY.EnQue(yLocal);
    }
    
    // 计算函数
    __aicore__ inline void Compute(int32_t progress)
    {
        LocalTensor xLocal = inQueueX.DeQue();
        LocalTensor yLocal = inQueueY.DeQue();
        LocalTensor zLocal = outQueueZ.AllocTensor();
        
        Add(zLocal, xLocal, yLocal, TILE_LENGTH);
        
        outQueueZ.EnQue(zLocal);
        inQueueX.FreeTensor(xLocal);
        inQueueY.FreeTensor(yLocal);
    }
    
    // 搬出函数
    __aicore__ inline void CopyOut(int32_t progress)
    {
        LocalTensor zLocal = outQueueZ.DeQue();
        DataCopy(zGm[progress * TILE_LENGTH], zLocal, TILE_LENGTH);
        outQueueZ.FreeTensor(zLocal);
    }

private:
    TPipe pipe;
    TQue inQueueX, inQueueY;
    TQue outQueueZ;
    GlobalTensor xGm, yGm, zGm;
};

```

### 4.4 核函数调用与验证

编写host侧应用程序调用核函数：

```
int32_t main(int32_t argc, char* argv[])
{
    // 初始化Device设备
    aclInit(nullptr);
    
    // 创建Context绑定设备
    int32_t deviceId = 0;
    aclrtSetDevice(deviceId);
    
    // 分配Host内存，并进行数据初始化
    aclrtStream stream = nullptr;
    aclrtCreateStream(&stream);
    
    // 设置参与运算的核数为8
    constexpr uint32_t blockDim = 8;
    
    // 用内核调用符>>调用核函数
    add_custom>>(x, y, z);
    
    // 同步流
    aclrtSynchronizeStream(stream);
    
    // 释放资源
    aclrtDestroyStream(stream);
    aclrtResetDevice(deviceId);
    aclFinalize();
    
    return 0;
}

```

## 5 Ascend C性能优化高级技巧

### 5.1 API使用优化

Ascend C提供了多种API优化技巧，可以显著提升算子性能：

- ​​在算子kernel类外创建和初始化TPipe对象​​：避免KernelExample对象的内存被外部污染的风险，触发编译器对类内Scalar的编译优化，减少算子Scalar指令耗时。
- ​​通过TQueBind接口实现VECIN和VECOUT内存复用​​：对于纯搬运类算子，使用TQueBind接口可以避免LocalTensor到LocalTensor的DataCopy指令，减少无谓的vector消耗。
- ​​通过SetMaskCount接口开启Counter模式​​：简化mask处理逻辑，减少代码量和Scalar计算量。

### 5.2 内存访问优化

内存访问是影响算子性能的关键因素，以下是一些有效的优化策略：

- ​​地址对齐​​：确保workspace地址512B对齐，避免低效的搬运操作。使用SetGlobalBuffer接口设置workspace起始地址时，强制地址512B对齐：

```
uint64_t workspaceOffsets = (workspaceOffsets + qPostBlockTotal * sizeof(float) + ADDR_ALIGN_SIZE) / ADDR_ALIGN_SIZE * ADDR_ALIGN_SIZE;

```

- ​​数据排布优化​​：将输入数据排布格式从SBH更改为BNSD后，数据搬运连续，不需要跳地址读取数据，搬运效率可提升一倍。

### 5.3 计算任务优化

针对计算任务的优化策略包括：

- ​​Tiling基本块调整​​：在满足UB空间大小够用的情况下，tiling基本块切分的越大越好，减少循环次数。
- ​​CV流水并行​​：通过缓存机制实现让matmul提前计算多块，减少CV之间的通信次数，提高并行度。
- ​​核间负载均衡​​：特别是在casual场景下，需要将计算量均匀分配到多个核上，避免某些核计算量过大成为性能瓶颈。

## 6 实战案例：FlashAttention算子优化

LLM的Attention部分给计算系统带来巨大的计算和访存压力。基于Ascend C编程语言优化实现FlashAttention融合算子，可以充分利用片上缓存，提升Attention处理性能。根据实测，在一些典型场景中CANN的FlashAttention算子相比小算子取得了5倍以上的性能提升。

### 6.1 优化策略

FlashAttention算子的优化策略包括：

- ​​Tiling优化​​：将基本块大小从(64, 128)增大到(128, 128)，循环计算次数从32次减少到16次，性能提升一倍。
- ​​CV流水并行​​：实现mm1、mm2和mm3缓存优化，使Vector计算更密集，提高并行度。
- ​​核间负载均衡​​：将计算块均匀分到多个核上计算，每个核的计算量均匀，性能提升一倍。
- ​​FixPipe优化​​：通过workspace地址512B对齐，fixpipe时间减半，实测算子性能提升45%。
- ​​MTE2优化​​：优化数据排布格式，搬运效率提升一倍，异常搬运时长降低一半，实测算子性能提升30%。

### 6.2 性能收益

通过以上优化策略，FlashAttention反向算子在典型场景中实现了4倍左右的性能提升。

## 7 调试与验证技巧

### 7.1 孪生调试

Ascend C提供​​孪生调试​​功能，可以在CPU侧模拟NPU侧的行为进行调试。这大大减少了对实际NPU资源的依赖，提高了调试效率。

开发者可以使用标准的GCC编译器编译CPU侧代码，并使用GDB等通用调试工具进行单步调试，精准验证程序执行流程是否符合预期。

### 7.2 Profiling工具使用

利用Profiling工具分析算子性能瓶颈，识别优化机会：

- ​​aic_fixpipe_ratio​​：如果占比极高（如81%），可能出现严重的搬运瓶颈，需要检查地址对齐。
- ​​mte2_ratio​​：如果占比高，表明cube MTE2存在明显bound，需要优化数据排布。
