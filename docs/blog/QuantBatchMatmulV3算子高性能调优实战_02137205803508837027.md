# 第1章 概述

### 1.1 博客背景与目的

在昇腾NPU量化Matmul算子开发中，完成基础功能实现与存储优化后，如何充分释放NPU的硬件算力、优化流水线调度，是实现算子高性能的核心。昇腾NPU的AI Core包含Cube矩阵计算单元与Vector向量计算单元，支持多核并行、流水线重叠、UnitFlag同步机制等优化手段，可有效提升算力利用率、消除指令断流。本文基于昇腾课件学习与实验实操，详细讲解QuantBatchMatmulV3算子的算力优化（多核并行、负载均衡）与流水线优化（UnitFlag机制、计算与搬运重叠），通过实操验证调优效果，帮助昇腾开发者掌握昇腾NPU算子高性能调优的核心方法论，内容首发于昇腾社区硬件版块，严禁转载。

### 1.2 核心技术点

本文核心围绕昇腾NPU算子高性能调优展开，重点讲解两大调优方向：一是算力优化，通过多核并行调度、负载均衡，充分利用昇腾NPU的多核算力；二是流水线优化，通过UnitFlag同步机制、计算与搬运重叠，消除指令断流，提升流水线利用率。涉及的昇腾核心技术包括：昇腾NPU AI Core多核架构、Cube单元算力原理、UnitFlag同步机制、昇腾多核并行API、流水线调度实现。

## 第3章 配置参数

### 3.1 多核并行配置参数

本次实验采用多核并行调度，将矩阵乘任务拆分到多个AI Core执行，核心参数如下，参考昇腾多核并行API的要求：

1. 硬件参数：

- npu_id：NPU设备ID，取值为0（使用第一颗NPU）；

- ai_core_num：参与并行的AI Core数量，取值为16、32、64（分别验证不同并行度的优化效果）；

2. 任务拆分参数：

- split_dim：任务拆分维度，取值为“M”（沿矩阵A的行数M维度拆分）；

- split_size：每个AI Core承担的任务量，split_size = M / ai_core_num（确保任务均分，负载均衡）；

3. 负载均衡参数：

- balance_threshold：负载均衡阈值，取值为0.05（任务分配偏差不超过5%）；

- schedule_mode：调度模式，取值为“static”（静态调度，提前分配任务）。

### 3.2 UnitFlag流水线配置参数

UnitFlag机制用于优化流水线同步，将指令级同步改为分形级同步，核心参数如下：

1. 同步参数：

- unit_flag_enable：是否开启UnitFlag机制，取值为true；

- sync_level：同步级别，取值为“fractal”（分形级同步）；

2. 分形参数：

- fractal_num：每个AI Core处理的分形数量，取值为16（匹配NZ格式的分形尺寸）；

- mmad_num_per_fractal：每个分形包含的MMAD指令数量，取值为16（匹配Cube单元计算特性）。

### 3.3 实验对比参数

本次实验设置四组对比，验证不同调优手段的效果，所有组均开启NZ格式+双页表优化：

1. 基础优化组：NZ+双页表，无多核并行、无UnitFlag；

2. 多核16组：NZ+双页表+16个AI Core并行，无UnitFlag；

3. 多核32组：NZ+双页表+32个AI Core并行，无UnitFlag；

4. 全优化组：NZ+双页表+64个AI Core并行+UnitFlag机制。

四组实验的矩阵维度、量化参数与前两篇博客一致，确保对比的公平性。

### 4.2 UnitFlag流水线优化源码修改

在quant_batch_matmul_v3.cc中添加UnitFlag机制配置逻辑，优化流水线同步：

```

// UnitFlag机制配置
void SetUnitFlag() {
    // 开启UnitFlag机制，分形级同步
    aclPipelineSetUnitFlag(ACL_PIPELINE_UNIT_FLAG_ENABLE, ACL_PIPELINE_SYNC_LEVEL_FRACTAL);
    // 配置分形数量与MMAD指令数量
    aclPipelineSetFractalParam(16, 16);
    // 配置计算与搬运重叠
    aclPipelineSetOverlapMode(ACL_PIPELINE_OVERLAP_ENABLE);
}

// 在算子初始化函数中调用UnitFlag配置
