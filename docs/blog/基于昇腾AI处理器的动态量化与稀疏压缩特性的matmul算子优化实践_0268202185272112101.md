# 1. 背景

## 1.1 问题

Pangu-7B模型搭载310P硬件，在MLP层进行gate_up_proj层和down_proj层计算时，采用W8A8+静态量化的组合，并结合310P的硬件特性（片上有unzip模块，可进行片上的无损解压缩），应用稀疏特性和压缩特性。但实测静态量化+稀疏特性组合不满足精度要求，为此，在down_proj层计算时回退处理（gate_up_proj采用INT8计算，而down_proj采用FP16计算，通过提高数据表达范围来提升结果精度，但存在性能和内存消耗，实测性能劣化点也发生在down_proj层），通过牺牲性能保证精度要求。故当前的优化目标为：在使用稀疏特性+压缩特性基础上，不回退down_proj层即可达到精度要求。

## 1.2 方案探索

在模型调试时，尝试过多种方案，但均无法同时满足性能与精度要求，如减少down_proj回退层数来实现性能与精度平衡，实测精度不达标；如将静态量化替换为动态量化，稀疏+压缩替换为普通量化矩阵计算，性能提升不明显。

最后确认探索方向为W8A8量化+SC特性（S-稀疏+C-压缩）+混合量化（prefill阶段使用动态量化，decode阶段使用静态量化）。

## 1.3 融合算子

确认了探索方向后，prefill阶段的稀疏+动态量化功能需要新算子来承载该部分能力，为此需进行融合算子的开发。

## 2.1 算子功能

功能点解释：

动态量化：量化为对权重和激活值都做量化，将高位浮点数转为8 bit，可以直接减少模型权重的体积，带来性能收益。静态量化使用预先确定的量化参数进行量化，动态量化使用输入数据在线计算量化参数进行量化。

稀疏：模型稀疏工具通过算法判断模型权重中每个元素对精度结果的重要性，并将模型权重中对最终精度影响小的权重值置零。

压缩权重：权重压缩工具将模型权重通过压缩算法进一步编码压缩，最大程度地降低权重体积，生成压缩后权重和索引文件。

反量化：将低精度（如 INT8）的量化权重或激活值，转换回原始浮点精度（如 FP16/FP32），以恢复数值表达范围或适配高精度计算需求。

# 4.性能优化实践

在Matmul运算的过程中伴随着大量的数据传输过程，左右矩阵数据需要被多次传输给AICORE用于计算，基于昇腾芯片的Matmul计算前数据搬运过程包含由核外内存GM到L1的一级搬运以及由L1到L0的二级搬运。由于GM和L1的读写速率存在较大差异，存在L2缓存，用于缓存数据，减少搬运量。首先需确认数据搬运是否存在性能瓶颈。

分析性能穿刺的profiling数据，观察内存负载分析数据，L1写入带宽为194.41GB/s，与L2 Cache写入带宽接近，L2 Cache命中率较低，只有16.29%，即存在大量数据未使用L2缓存，直接从GM搬运至L1中。故需对L2缓存进行优化。

 

## 4.1 L2 Cache优化

### 4.1.1 Swizzle策略

数据搬运时，先从GM搬运至L1，然后将左右矩阵（下图中A、B矩阵）计算子矩阵单元从L1搬运至L0A/B，Cube矩阵计算输出C矩阵到L0C。以C矩阵行优先循环方式为例（下图以301P举例，AIC核数为8，C矩阵中序号代表AIC核编号），完成C矩阵单行计算时，A矩阵参与计算数据量为m0*k，B矩阵参与计算为k*n，若B矩阵较大，k*n超过L2缓存大小，则后续计算时，B矩阵将被反复搬运，未使用L2缓存，增大了数据搬运量。

 

对于这种大矩阵计算行/列循环策略下，L2缓存命中率较低的场景，当前存在优秀实践Swizzle策略能显著改善该问题，使用和调整Swizzle策略有助于提高缓存命中率、减小数据读取开销，从而提高矩阵乘整体计算效率。常用swizzle策略： 

   

图中每一个方块表示C矩阵的一个基本块，方块中的序号代表AI Core的编号（该示例中假设AI Core数量为20）。箭头方向指示了特定Swizzle策略下基本块的遍历顺序，我们按照该顺序将基本块依次分配给AI Core进行处理，编号0~19的20个基本块是并行计算的。

确认Swizzle策略参数存在多种思路，当前算子实现时，以减少搬运数据为基准，通过减少单次或者单轮循环数据量为准：方向上，比较m和n大小，m较大时，选择SwizzleDirection为0，n较大时，选择SwizzleDirection为1；偏移上，选择使单轮循环跑满核时，搬运数据量最小的偏移量，即根据矩阵大小计算使下图中n0*k*offset + m0*k*blockDim/offset最小，减少单轮的搬运量，增大数据放入L2的几率。

### 4.1.2 进一步分析

原方案的L2命中率为什么这么低？带着这个问题，我们继续分析。

原方案使用的是列循环，即C矩阵采用列优先策略循环，计算单列时，B矩阵即右矩阵单列不变，A矩阵即左矩阵行循环。如果采用行循环，即C矩阵采用行优先策略循环，结果会有差异吗？典型shape下测试结果L2缓存命中率如下：

典型shape Case1 Case2 Case3 Case4

L2命中率 91.67% 89.42% 81.95% 85.83

算子耗时(us) 2325.43 2495.59 19584.42 8365.06

结果完全超出预期，均比列优先循环命中率高，且比Swizzle的命中率还高，性能也存在一定提升。需继续分析该问题。

对算子实现进行分析发现，B矩阵即右矩阵为权重压缩矩阵，计算时，根据压缩索引到GM中解压权重矩阵，然后从GM搬运到L1，搬运过程中，会将解压缩后的数据放入L2缓存，但索引信息与缓存信息数据不匹配，无法命中L2缓存，且会占用L2缓存空间，导致左矩阵可使用L2缓存减小，且由于左矩阵较大，使得左矩阵缓存命中率更低。

为验证该现象，将典型shape Case1中左矩阵shape减小，由K4096,N2560,M8192改为K4096,N2560,M4096（即减小左矩阵大小），L2缓存命中率由16.29%增长为31.14%，验证了上述分析。

在当前算子使用场景下，权重压缩矩阵搬运数据时，无法进行L2缓存命中，且会占用L2缓存空间，影响整体缓存命中率，这种场景下，原Swizzle设定策略并非最优循环策略，优先使用行优先循环策略（从循环逻辑来看，行优先也是一种swizzle类型，SwizzleDirection为0，SwizzleOffset为1）。

## 4.2 流水优化与数据预存

当前性能依然无法满足使用要求，需继续进行分析，完成L2缓存命中率提升后，L1的写入带宽提升至527.69GB/s，数据搬运瓶颈得到解决，需从数据处理逻辑入手优化。

从上述流程可知，bias向量的搬运涉及两个流程，GM=>UB涉及MTE2单元，UB=>L0C涉及VECTOR单元，第二个流程依赖最终结果输出到GM完成，正是由于此处的依赖，导致下一轮的矩阵计算mmad需要等待上一轮结果的搬出，导致MTE2存在空泡（计算矩阵由GM搬运至L1使用MTE2单元，L1到L0使用MTE1单元，矩阵乘等待阻塞MTE1搬运，进而影响MTE2搬运）。但这两个流程不存在相互耦合关系，需接触该依赖关系。

# 6.模型验证

本算子适用于310P芯片，使用了310P芯片的unzip模块，将动态量化输入与稀疏压缩矩阵相结合，保证精度的同时，提升算子性能。可用于Transformer结构模型的qkv计算（Query-Key-Value Projection）和o计算（Output Projection）中的矩阵乘计算，以及稀疏MoE模型MLP层中GateUp计算和Down计算（专家计算与聚合）中的矩阵乘计算。

使用该算子在Pangu-7B模型上进行验证，性能达标，抽取的测试集上平均精度提升达到4.04%，满足性能和精度要求。

# 7.思考点

- 对于L2缓存的优化，存在众多优秀实践，其中的Swizzle策略能显著提升L2缓存命中率，使用前需结合场景，对具体问题需具体分析；
- 使用压缩权重矩阵时，在GM搬运至L1时，无法发挥L2缓存功能，流程设计时，需纳入考虑，减少对L2缓存的影响；
- 融合算子的流程可灵活取舍，当前算子实施时，基于人力和快速验证考虑，未采用单个融合算子实现所有功能，而是使用已有融合算子+新开发融合算子的结合，最终实现也达到了性能要求；
- 最终性能和精度已达标，但存在三个流程可继续优化：a. 流程优化：优化transdata流程，将融合算子数据类型改为ND输入，精简流程；b. 性能优化：DoubleBuffer只在matmul计算中，反量化需等待mmad完成后启动，可将DoubleBuffer应用到反量化计算中，提高流水并行；c. 大融合算子思路：采用原来融合算子流程，将动态量化+Transdata+MatmulSC+Dequant放入单个融合算子，该融合算子能实现动态量化、压缩权重矩阵解压缩、矩阵乘、反量化等计算流程。
